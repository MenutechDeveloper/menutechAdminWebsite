================================================================================
MODO COMISIÓN MENUTECH — CÓMO FUNCIONA HOY Y CÓMO AUTOMATIZARLO
================================================================================

RESUMEN (1 minuto)
--------------------------------------------------------------------------------
Hoy el modo comisión NO es automático. Está a medias:
- La comisión (application_fee) SOLO se cobra si el restaurante tiene una cuenta
  Stripe Connect vinculada.
- Si NO tiene cuenta Connect, el código IGNORA la comisión y cobra TODO a tu
  cuenta. El reporte solo calcula la comisión "en pantalla".
- NO existe nada que envíe el dinero a la cuenta bancaria del restaurante. Eso hoy
  lo haces tú a mano.

¿SE PUEDE SEPARAR "COMISIONES" DE "CONNECT" (que el usuario NO se registre en Stripe)?
--------------------------------------------------------------------------------
Respuesta corta: NO del todo. En Stripe no existe forma de enviar dinero a la
cuenta bancaria de alguien sin que ese alguien tenga una cuenta Connect que lo
reciba. Stripe lo dice textual en su documentación (Manage payout accounts for
connected accounts):

  "Learn how to manage external bank accounts and debit cards for CONNECTED
   ACCOUNTS."

Es decir, para hacer un payout a un banco, el destino SIEMPRE tiene que ser una
cuenta Connect. No hay atajo.

PERO: "Connect" no obliga al restaurante a usar Stripe para su negocio. Hay
cuentas Connect de tipo "recipient" (solo reciben dinero) que son mucho más
ligeras que la típica Express: el restaurante solo da sus datos y su banco una
vez y ya. No ve un dashboard de Stripe ni cobra a sus clientes por su lado.

CONCLUSIÓN HONESTA
--------------------------------------------------------------------------------
No puedes tener comisiones 100% automáticas sin Connect. Las dos únicas opciones
reales son:

  OPCIÓN A — Connect "recipient" (semi-automática, recomendada)
  - El restaurante hace UNA vez un mini-registro (datos + cuenta bancaria) en el
    formulario seguro de Stripe.
  - Después: cliente paga -> Stripe deposita en el restaurante y retiene tu
    comisión -> Stripe hace el payout a su banco.
  - TODO automático a partir de ahí. Tú no haces nada.

  OPCIÓN B — Todo a tu cuenta (como hoy)
  - Todo el dinero entra a tu Stripe.
  - Tú transfieres a cada restaurante a mano (o con un script que use la API de
    Transfers).
  - OJO: para que la API de Transfers funcione, el destino TAMBIÉN necesita una
    cuenta Connect. Así que igual acabas usando Connect, solo que tú disparas la
    transferencia.

En resumen: el modo comisión NO puede ser automático sin Connect. La diferencia
con "Own Stripe" es solo QUIÉN se queda la comisión y QUÉ TAN LIGERO es el
registro del restaurante, no si se usa Connect o no.

QUÉ QUIERE DECIR "EN MODO COMISIÓN, EXIGIR CUENTA CONNECT ACTIVA"
--------------------------------------------------------------------------------
Hoy el código deja autorizar el modo comisión aunque el restaurante NO tenga
cuenta Connect. En ese caso pasa esto (archivo stripe-payment/index.ts):

  // Solo reparte si hay cuenta Connect
  if (stripeAcc && stripeAcc.stripe_account_id && stripeAcc.charges_enabled) {
     params.append("payment_intent_data[transfer_data][destination]", ...);
     // ... aquí se aplica el application_fee (tu comisión)
  }

  Si NO hay cuenta Connect -> no entra al if -> se cobra TODO a tu cuenta y la
  comisión NO se retiene. El reporte la muestra, pero no mueve dinero.

"Exigir cuenta Connect activa" significa: bloquear la autorización del modo
comisión hasta que el restaurante tenga una cuenta Connect con charges_enabled.
Así te aseguras de que la comisión SÍ se cobre de verdad y no se te escape.

POR QUÉ (técnico)
--------------------------------------------------------------------------------
Archivo: supabase/functions/stripe-payment/index.ts
- El bloque que reparte el dinero (`payment_intent_data[transfer_data][destination]`
  + `payment_intent_data[application_fee_amount]`) solo se ejecuta si existe
  `menutech_stripe_accounts.stripe_account_id` con `charges_enabled = true`.
- Si no existe, se cobra todo a la plataforma y la comisión queda solo en el reporte.

DÓNDE VA LA CUENTA BANCARIA DEL USUARIO
--------------------------------------------------------------------------------
- NUNCA en tu base de datos ni en un formulario tuyo.
- Los datos bancarios se capturan en el onboarding seguro de Stripe Connect.
- Tú solo guardas el `stripe_account_id` (acct_xxx) en `menutech_stripe_accounts`.
- El dinero del restaurante cae directo a SU cuenta Stripe y de ahí a SU banco.

QUÉ CONFIGURAR EN TU CUENTA DE STRIPE
--------------------------------------------------------------------------------
1. Activar Connect: Dashboard -> Connect -> "Get started".
2. Completar tu "Platform profile" (tipo de negocio y responsabilidades de
   pérdidas / cobro de fees). Si falta, Stripe rechaza crear cuentas.
3. Cuentas tipo Express o "recipient" (la más ligera para comisiones).
4. Supabase -> Project Settings -> Edge Functions -> Secrets:
   - `stripe_api`            = sk_live_... / sk_test_...
   - `stripe_publishable`    = pk_live_... / pk_test_...
   - `stripe_webhook_secret` = whsec_... (del webhook)
5. Webhook: crear endpoint `stripe-webhook` y suscribir eventos
   `checkout.session.completed`, `account.updated`, etc.

QUÉ FALTA EN EL CÓDIGO (para que sea automático de verdad)
--------------------------------------------------------------------------------
1. En modo comisión, EXIGIR cuenta Connect activa (hoy lo permite sin cuenta y
   termina cobrando todo a la plataforma sin retener tu comisión).
2. Mantener destination charge + application_fee (ya está; solo falta el punto 1).
3. Guardar en el webhook la comisión real aplicada (hoy el log no la registra).

NOTA IMPORTANTE
--------------------------------------------------------------------------------
El modo "Own Stripe" y el modo "Comisión" usan la MISMA mecánica de Connect. La
diferencia es solo quién se queda la comisión:
- Own Stripe  -> comisión 0% (todo al restaurante).
- Comisión    -> comisión X% (tu parte se retiene automáticamente).
